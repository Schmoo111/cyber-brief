Java4Shell: a flaw in Java that could allow takeover without a login

Background: Java is a programming platform that runs a large share of business software worldwide, from banking back-office systems to everyday workplace tools. OpenJDK is the free, open-source version of Java that most companies' Java comes from, including Oracle's. The name echoes "Log4Shell", a Java-related flaw from 2021 that caused worldwide emergency patching, but the two are different flaws.

What happened
Researchers at Calif, a security firm, disclosed a flaw in the part of Java that decodes Base64, a very common way of packaging data in web traffic and login tokens. A specially malformed piece of text can make Java write data where it shouldn't. Calif says that can be turned into a full takeover, without needing a password.[12]
Who is exposed
Java 17 and newer, but only on servers with certain recent Intel and AMD processors (those supporting a feature called AVX-512). Servers on ARM chips, and the older Java 8 and 11, are generally not affected.[12][13]
Products shown at risk
Calif says it took over default installations of Jira and Confluence (Atlassian's widely used project-tracking and team-wiki tools), Jenkins (a tool that builds and releases software), Keycloak and PingFederate (login and single-sign-on systems), and JFrog Artifactory (a store for software components). Others, such as Kafka and Elasticsearch, needed a login first. Calif says the list is not complete.[12][14]
Status
No attacks reported so far, and it is not on CISA's exploited list. Calif is holding back its full attack code, but other researchers have reproduced crashes and one says he has a working exploit. Oracle released fixes on 17 Nov; Amazon and Azul have fixed their versions of Java, while Red Hat and some others had not yet.[13][14]
Action
Upgrade Java to the 17 November 2026 release or newer from your Java supplier. Products that ship their own copy of Java (Jira, Jenkins and similar) need their own vendor updates. Until then, a startup setting can switch off the vulnerable feature.[12][14]
Why it matters
Banks run a great deal of Java, including the login and developer tools named above. Even without known attacks yet, flaws like this are usually exploited quickly once details spread, so this should be near the top of patching lists.

Kokoro AI voice model: publisher's account taken over

Kokoro is a free AI model that turns text into natural-sounding speech with millions of downloads a month. Hugging Face is the main public website where AI models are shared and downloaded, a bit like an app store for AI.

What happened
Security researchers bought a web address the model's publisher had let expire. That let them reset the publisher's password and take over the account. They showed they could alter the model to say different words from the text it was given. They did this as a demonstration and did not release the altered version.[7] Details rest on one original report.
Why it matters
Banks increasingly build public AI models into their tools. If an attacker controls a publisher's account, they can quietly swap in a tampered model. Only use models from verified sources, and lock to a specific checked version.

No new confirmed cyberattack on a bank or payments firm was found. JPMorgan Chase, the largest US bank, still says its 16 Nov outage was a software fault, not an attack.[8]

Optimizely website attack

Background: Optimizely's tool works by loading a small piece of code from Optimizely onto each customer's web pages. On 16 Nov an attacker used a flaw in Optimizely's sign-up process to change that code for 178 customers. Visitors to those sites unknowingly ran code that tried to copy card details typed into payment forms ("card skimming"), swap cryptocurrency payment addresses for the attacker's, and attack iPhones. Report URI, the web-security firm that uncovered it, raised the alarm.

What's new
Banks and finance were the largest group hit: 32 organisations, plus 6 crypto-trading and 6 insurance firms.[1] Named firms include:
  • HSBC, a UK-based global bank (sites in 11 countries)
  • ABN AMRO, a major Dutch bank
  • Equifax, one of the three big credit-reporting agencies
  • Hang Seng Investment, the fund arm of a large Hong Kong bank
  • Funding Circle, a UK online lender to small businesses
Timeline
The card-stealing code was active for several hours on 16 Nov. All affected files were cleaned by late that night (UTC).[1]
Optimizely says
The flaw is fixed, the code removed, and affected customers contacted directly.[2]
Action
If you or your suppliers use Optimizely, check for unauthorised code, reset access credentials, and assess whether customers who paid on 16 Nov need notifying.

n0n's claims against Visa, Mastercard, JPMorgan and Walmart

Background: n0n is a criminal group, first seen in September 2026, that steals data and threatens to publish it unless paid (extortion). On 16 Nov it named Visa and Mastercard (the two biggest card payment networks), JPMorgan Chase (the largest US bank) and Walmart (the world's largest retailer) on its website, and gave them 48 hours to pay.

Confirmed
Visa says one of its suppliers in Asia-Pacific had a security incident, but no card data was affected.[8]
Unconfirmed
No data has been published. Mastercard and Walmart have said nothing. n0n claims marketing and booking records, not card numbers or passwords. Researchers suspect a marketing supplier shared by these firms, but this is unproven.[6]
Credibility
Security firm Bitdefender found n0n claimed 149 victims in October but had evidence for only about 20.[6]

TSMC employee data leaked

TSMC (Taiwan Semiconductor Manufacturing Company) makes most of the world's advanced computer chips for firms such as Apple and NVIDIA.

Confirmed
TSMC says data on current and former employees appeared on a criminal website. It came from an unnamed cloud-storage supplier, not TSMC's own systems.[9]
Claimed
The seller claims 46,000 records.
Why it matters
Another case of data leaking through a supplier. Low direct risk to banks.

Glossary

Java / OpenJDK
Java is a programming platform used to build and run a large share of business software. OpenJDK is its free, open-source core, which Oracle, Amazon, Red Hat and others package as their own versions.
Remote code execution
When an attacker can make someone else's computer run commands of their choosing over a network. Usually the most serious kind of flaw.
Base64
A common way of turning data into plain text so it can travel safely in web pages, emails and login tokens.
CVE
A standard ID number given to each publicly known software flaw, e.g. CVE-2026-115731.
CISA exploited list (KEV)
The US cyber agency's list of flaws it has confirmed attackers are actively using. US federal agencies must fix them by a deadline; it is a good priority list for everyone.
Supply-chain attack
Attacking a supplier's product so that the damage spreads to all of that supplier's customers.
Card skimming
Hidden code on a payment page that copies card details as customers type them.
Extortion group
Criminals who steal data and demand payment to not publish it.
Puppet server / agents
In Puppet Enterprise, the central server that sends configuration instructions, and the helper programs on each managed server that receive them.
Certificate
A digital ID card that lets computers prove who they are to each other.
AI model
The trained "brain" file behind an AI tool. Swapping it changes what the tool does without changing the app around it.
