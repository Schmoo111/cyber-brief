CriticalConfidence: MediumEspionage-style intrusion

Check Point management servers hijacked at 22 organisations

Background: Check Point is an Israeli-founded maker of firewalls, the devices that filter traffic in and out of a network. Its Security Management servers hold the rules for every firewall a firm runs, so controlling one is like holding the master keys. GreyNoise, a threat-intelligence firm that watches internet scanning, found the campaign.

Researchers found (GreyNoise)
At least 22 victims in energy, engineering, financial services, government, manufacturing, mining and transport, in the US, UK, Australia, Germany, Hong Kong and elsewhere. Activity was seen from 17 Oct to 2 Nov; one victim's server was used to collect data stolen from 24 Check Point servers. GreyNoise believes access persists.[1]
Method
The attacker used AI "agentic" tools, which plan and carry out steps on their own, to find and exploit weak systems, with a human stepping in. A dozen known flaws were used or tried, including in Check Point SmartConsole, Citrix NetScaler, Ivanti, Exchange and vCenter. The entry point is unknown.[1]
Actor
Tracked as GT13; origin unknown. No Check Point statement or patch was seen.
Why it matters
Check every Check Point management server for unexpected logins, shared SSH keys and odd bulk tasks; keep management interfaces off the internet.
HighConfidence: MediumSupplier breach

Radware: customers' log-storage keys exposed

Background: Radware is an Israeli security firm selling protection against website attacks and floods of junk traffic (DDoS). Its Cloud WAF (web application firewall) screens traffic to customers' websites and can copy logs into the customer's own cloud storage, using keys the customer gives it.

Reported (Radware root-cause report, via BleepingComputer)
On 19 Nov someone reached an internal management API that needed no login. Radware spotted it about ten hours later and shut it off. Customer contact details and, for some customers, keys to their AWS, Azure or SFTP log storage were exposed. Radware says website protection and customer traffic were not touched.[2]
Unknown
Whether the keys were misused; some customers saw AWS alerts about an unfamiliar address. No public statement from Radware was seen. Attacker unknown.[2]
Action
Replace Cloud WAF log-export keys and check storage logs since 19 Nov.
HighConfidence: HighNew critical flaws

VMware: new critical vCenter and ESX flaws

Background: VMware, owned by Broadcom, makes the software that runs most banks' virtual servers. ESX is the layer that runs the virtual machines; vCenter is the console that controls them all. An "authentication bypass" lets someone in without valid credentials; an "out-of-bounds write" lets crafted data spill into memory it shouldn't touch, which can let an attacker run code.

Confirmed (Broadcom)
23 fixes. A vCenter directory-service login bypass (9.8 of 10) lets anyone who can reach vCenter on the network get in. Two ESX flaws (9.8) can lead to code running on the host itself.[3][4]
Status
Not reported as exploited. VMware says the new vCenter flaw is unrelated to the one exploited by the Armory Castle espionage group last week.[3]
Action
Upgrade vCenter and ESX to the latest fixed versions; vCenter 7.0 has no fix listed.

92-minute security fix

Add a passkey to your main email account 2 minutes · phone · your personal Google or Microsoft account

Why now: today's phone-scam crew talks people into reading out a one-time code or approving a login prompt on a fake sign-in page. A passkey can't be read out or typed into a fake site: it only works on the real website, unlocked by your face, fingerprint or phone PIN.

  1. Google: open your Google Account, tap Security (may say "Security & sign-in"), then Passkeys and security keys and Create a passkey. Confirm with your face, fingerprint or PIN.
  2. Microsoft (Outlook, Hotmail): sign in to your Microsoft account page, open Security, then Manage how I sign in (may say "Advanced security options") and choose to add a passkey or "face, fingerprint, PIN or security key".
  3. Next time you sign in on that device, pick Use a passkey instead of typing your password.

Done when: the account's security page lists a passkey for your phone. Remember: no genuine bank, Google or Microsoft caller will ever ask you to read out a code. Bonus: set one up with a parent too.

For your work devices and accounts, leave this to your IT team.

Glossary

Passkey
A sign-in that replaces your password with your phone's face, fingerprint or PIN check; it only works on the genuine website, so it can't be phished.
Firewall management server
The central server that stores and pushes the rules for all of a firm's firewalls.
Agentic AI tools
AI systems that plan and carry out a series of steps themselves, such as scanning and exploiting.
SSH key
A digital key used to log in to servers remotely without a password.
WAF
Web application firewall: a filter that blocks attacks on websites.
DDoS
Distributed denial of service: flooding a service with junk traffic to knock it offline.
API
A connection that lets one piece of software ask another for data or actions.
SFTP
A secure way to transfer files between computers.
Authentication bypass
A flaw that lets someone in without valid credentials.
Out-of-bounds write
A flaw where data is written past the memory set aside for it, which can let an attacker run code.
Virtualisation (ESX, vCenter)
Running many "virtual" servers on one physical machine; ESX runs them, vCenter manages them.
Vishing
Voice phishing: scam phone calls to trick staff into giving access.
One-time code / push approval
Second-step login checks; a passkey cannot be phished this way.
Leak site
A website where extortion gangs post stolen data to pressure victims.
SQL injection
Slipping database commands into a website's input boxes to read or change its data.
Password hash
A scrambled form of a password; it can sometimes be cracked offline.
Backdoor
Hidden software that gives an attacker ongoing remote control.
IPFS
A public peer-to-peer network for storing and sharing files.
Open-source intelligence
Intelligence drawn from public information.
CISA exploited list (KEV)
The US cyber agency's list of flaws confirmed as used in attacks.
