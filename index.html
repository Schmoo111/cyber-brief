HighConfidence: MediumSupplier breach

SAP: attackers reportedly got into its code store

Background: SAP is a German software giant whose systems run accounting, payroll and supply chains at most large companies and banks. GitHub is a service where developers store and change code. A login token is a digital pass that lets someone act as a user without re-entering a password.

SAP confirmed
It spotted suspicious activity and acted quickly; "no evidence of unauthorized access to customer business data." It has not said which systems were hit or whether the incident is contained.[1][2]
Media reported
Der Spiegel, citing insiders, says attackers stole employees' GitHub tokens and used them to copy and change source code, possibly with AI tools. SAP reportedly restricted GitHub access, paused automated build processes and replaced the keys used to prove its software is genuine (internal name "Project Granite"). Not independently verified.[1][2]
Actor
Unknown; no claim of responsibility.
Why it matters
If altered code reached customers, it would be a supply-chain attack on core banking back-office systems. Ask SAP for written guidance, watch for updates signed with new keys, and check any code you pull from SAP's public GitHub.

UK benefits department takes services offline

Background: The Department for Work and Pensions (DWP) is the UK's largest government department by spending; it pays the state pension and most benefits.

Confirmed (DWP)
Some online services were taken offline "as a precaution" after a cyber incident; payments will be made as normal. DWP is working with the National Cyber Security Centre (NCSC). The nature of the incident, any data loss and the attacker are not disclosed.[3]
Why it matters
Millions of UK bank customers receive DWP payments. Expect scam calls and texts posing as DWP or as banks "helping" with payments; brief fraud and contact-centre teams.
HighConfidence: HighNew vulnerability

NFS2ROOT: remote takeover of Linux file servers

Background: NFS is the standard way Linux machines share folders over a network; the "kernel" is the core of the operating system. This flaw is a heap buffer overflow: the server copies more data into a memory area than it can hold, letting an attacker overwrite memory and then run code as root, the all-powerful account.

Disclosed
CVE-2026-99362 affects Linux kernels going back to 2014 when the NFS server is running (versions 4.1 or 4.2) and its network port (2049) is reachable. No password or user action needed. Found by France's cyber agency ANSSI; security firm OpenSec built a working exploit but has not published it. No exploitation reported.[4]
Action
Install your Linux vendor's kernel update and reboot; meanwhile limit port 2049 to trusted machines or turn off the NFS server where unused.
MediumConfidence: HighUnpatched flaw

Cacti: public attack code, no fix

Background: Cacti is free software that draws graphs of network and server health. The flaw (nicknamed 4HTTP2SHELL) lets a "guest" visitor save a booby-trapped setting that the software later passes, unchecked, to a system command, so four web requests give full control.

Reported
Affects the latest version, 1.2.31, only where the guest account is switched on (off by default). Attack code is public on GitHub; no CVE and no fix yet. Exploitation not reported.[5]
Action
Turn off Cacti guest access and keep its web page off the internet.

82-minute security fix

Check your email account's recent security activity 2 minutes · phone or laptop · Google (Gmail) or Microsoft (Outlook/Hotmail)

Why now: pCloud users got "new device" alerts after an attack, and some alert links pointed somewhere odd. Your email account is the key to resetting everything else, so look at its own activity list directly, never through a link in an email.

Where it lives depends on your email:

Google / Gmail
  1. Type myaccount.google.com into your browser yourself and sign in.
  2. Tap Security (may say "Security & sign-in").
  3. Open Recent security activity and check each event was you.
  4. If not, tap No, secure account (may say "Don't recognise it?").
Microsoft / Outlook
  1. Type account.microsoft.com into your browser and sign in.
  2. Choose Security, then Sign-in activity (may say "View my activity").
  3. Expand any sign-in from a place or device you don't know.
  4. If it wasn't you, choose Secure your account and change the password.

Done when: every recent sign-in and change is one you recognise. If you can't find the list, change your password and make sure two-step verification is on. Bonus: check a parent's account with them.

For your work devices and accounts, leave this to your IT team.

Glossary

Token
A digital pass a system issues after login, used instead of re-entering a password.
Source code
The human-written instructions that make up a program.
Code-signing key
A secret key a software maker uses to stamp its updates as genuine.
Supply-chain attack
Hacking a supplier to reach its customers.
Kernel
The core of an operating system, controlling memory and hardware.
NFS
Network File System: the standard way Linux and Unix machines share folders over a network.
Buffer overflow
Putting more data into a memory area than it can hold, spilling into and overwriting nearby memory.
Root
The all-powerful administrator account on a computer.
Exploit / proof of concept
Code that shows or uses a flaw in practice.
Zero-day
A flaw attackers can use before the maker has released a fix.
Guest account
A login that lets anyone view parts of a system without their own account.
AI agent
AI software that takes actions on its own toward a goal, such as scanning and attacking systems.
Password manager
An app that stores your passwords in an encrypted "vault" unlocked by one master password.
KEV list
CISA's Known Exploited Vulnerabilities catalogue: flaws confirmed as used in real attacks.
CVE
The standard ID number given to a publicly known security flaw.
Two-step verification
A second check at login, such as a code or phone prompt, on top of the password.
